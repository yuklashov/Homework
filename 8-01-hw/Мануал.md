# Мануал по выполнению ДЗ 8.01 «Git»

## Цель домашнего задания:
Освоить базовые команды Git: настройка, работа с коммитами, ветками, файлом `.gitignore` и разрешение конфликтов слияния.

## Этапы выполнения:

### 1. Начальная настройка Git
- **Задача:** Указать Git, кто будет делать коммиты. Это необходимо для всех репозиториев на данном компьютере.
- **Команды:**
  ```bash
  # Устанавливаем имя пользователя
  git config --global user.name "Yuklashov"

  # Устанавливаем email пользователя
  git config --global user.email "yuklashov@gmail.com"
  ```
- **Результат:** При создании коммитов теперь будет указываться заданное имя и почта.

### 2. Игнорирование файлов (`.gitignore`)
- **Задача:** Запретить Git отслеживать временные или служебные файлы (например, кэш, скомпилированные `.pyc` файлы).
- **Действия:**
  1. Создали в корне репозитория файл с именем `.gitignore`.
  2. Добавили в него строки с шаблонами файлов и папок, которые нужно игнорировать:
     ```gitignore
     *.pyc
     cache/
     ```
- **Результат:** Git больше не предлагает добавить файлы, соответствующие этим шаблонам, в коммиты. Это помогает поддерживать чистоту в репозитории.

### 3. Работа с ветками (Branching & Merging)
- **Задача:** Научиться вести разработку в отдельной ветке (`dev`) и вливать изменения в основную (`main`). Это стандартный рабочий процесс.
- **Основные команды:**
  ```bash
  # Создать новую ветку 'dev' и сразу переключиться на неё
  git checkout -b dev

  # ... делаем изменения в коде, добавляем коммиты в ветке dev ...
  git add .
  git commit -m "feat: Add new feature in dev"

  # Переключаемся обратно на основную ветку
  git checkout main

  # Вливаем все изменения из ветки 'dev' в текущую ('main')
  git merge dev
  ```
- **Результат:** Весь код, написанный в `dev`, был успешно перенесен в `main`. История коммитов в графе (network) показывает слияние веток.

### 4. Разрешение конфликтов слияния (Merge Conflicts)
- **Задача:** Смоделировать и решить ситуацию, когда Git не может автоматически объединить изменения из разных веток, так как они затрагивают одни и те же строки кода.
- **Действия:**
  1. Внесли конфликтующие изменения в один и тот же файл в ветках `main` и `conflict`.
  2. Попытались слить ветку `conflict` в `main` командой `git merge conflict`.
  3. Git остановил слияние и сообщил о конфликте (`CONFLICT (content): Merge conflict in ...`).
  4. Открыли конфликтный файл в редакторе. Увидели разметку Git:
     ```
     <<<<<<< HEAD
     код из текущей ветки (main)
     =======
     код из вливаемой ветки (conflict)
     >>>>>>> conflict
     ```
  5. Вручную отредактировали файл, оставив только нужную версию кода и удалив разметку Git.
  6. Завершили слияние, сообщив Git, что конфликт разрешен:
     ```bash
     git add .
     git commit -m "fix: Resolve merge conflict"
     ```
- **Результат:** Научились решать самую частую проблему при командной работе. Слияние было успешно завершено, история коммитов отражает разрешение конфликта.
