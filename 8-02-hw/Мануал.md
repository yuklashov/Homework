# Мануал по выполнению ДЗ 8.02 «Что такое DevOps. СI/СD»

## Цель домашнего задания:
Познакомиться с Jenkins и Nexus, настроить CI/CD процесс (сборка, тестирование и загрузка артефактов) как через графический интерфейс, так и с помощью Declarative Pipeline.

## Этапы выполнения:

### 1. Подготовка инфраструктуры
- **Сложности:** Требуются две виртуальные машины, одна для Jenkins, другая для Nexus.
- **Решение:** Использован Terraform (`main.tf`) для быстрого и автоматизированного развертывания двух инстансов в Яндекс Облаке. Для настройки ПО (установка Jenkins, Nexus, Go) написан Ansible-плейбук.

### 2. Задание 1: Jenkins Freestyle Project
- **Действия:** 
  1. Форк репозитория с исходным кодом.
  2. Установка плагинов Jenkins и настройка путей к интерпретатору Go (потребовалось установить `/usr/bin/go`, так как тесты написаны на этом языке).
  3. Создание проекта Freestyle. Указал ссылку на форк.
  4. Добавление шага сборки `Execute shell` с командой `go test .`.
- **Сложности:** Ошибка `go: command not found` при первой сборке.
- **Решение:** Предварительная установка пакета `golang` на сервер Jenkins через Ansible. Сборка прошла успешно, тесты зеленые.

### 3. Задание 2: Declarative Pipeline
- **Действия:** Перенос логики из графического интерфейса в пайплайн (код). 
- **Решение:** Создан Pipeline script, состоящий из стадий `Checkout` (стянуть код) и `Test` (выполнить команду `go test .`). Это позволило версионировать процесс сборки как код.

### 4. Задание 3 и 4*: Nexus и загрузка артефактов
- **Действия:**
  1. Развертывание Sonatype Nexus.
  2. Создание репозитория формата `raw (hosted)` с названием `netology-raw`.
  3. Добавление в Jenkins Pipeline шага компиляции: `go build -o myapp`.
  4. Добавление шага загрузки артефакта в Nexus с использованием `curl`.
- **Сложности:** Как сделать так, чтобы имена артефактов не перезаписывались, а сохраняли историю?
- **Решение (Задание 4*):** Использование встроенной переменной Jenkins `${BUILD_NUMBER}`. Команда загрузки была изменена таким образом, чтобы каждый загружаемый бинарник получал суффикс с номером сборки (например, `myapp-main-${BUILD_NUMBER}`). Теперь в Nexus хранятся все версии релизов по порядку.

---
**Итог:** Автоматизирован процесс от забора кода до публикации готового артефакта в хранилище. Все этапы задокументированы и готовы к дальнейшему масштабированию.
