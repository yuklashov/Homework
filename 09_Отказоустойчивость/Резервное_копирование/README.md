# Резервное копирование — Александр Юклашов

Выполнено самостоятельно 27 октября 2026. Две основные задачи оформлены; rsync реально проверен на временных файлах Mac, без чтения настоящей домашней папки и без установки cron. VM не использовались.

## 1. Зеркало без скрытых каталогов, с контрольными суммами

```bash
rsync -a --checksum --delete --exclude='.*/' -- "$HOME/" /tmp/backup/
```

Это справочная команда, на настоящем HOME не запускалась. `-a` сохраняет структуру/базовые атрибуты, `--checksum` сравнивает содержимое даже при одинаковых размере и mtime, `--delete` удаляет лишние объекты получателя, `'.*/'` исключает скрытые **каталоги** на любой глубине. Скрытый обычный файл `.profile` не исключается. Завершающий `/` у источника означает содержимое HOME без дополнительного уровня каталога.

По умолчанию исключённые каталоги также защищены от удаления в получателе; для зеркала выбранного набора используем отдельный исходно пустой backup. Не добавлять `--delete-excluded` к существующей копии без понимания, какие исключённые данные исчезнут. Rsync-контрольная сумма определяет необходимость копирования, а не создаёт отдельный долговременный SHA256-манифест.

## 2. Ежедневный скрипт + cron

[src/home-backup.sh](src/home-backup.sh) делает **полное** зеркало HOME в /tmp/backup (в том числе скрытые каталоги: второй пункт не требует исключения). Параметры для тестов передаются как BACKUP_SOURCE_DIR/BACKUP_TARGET_DIR. Защита от совпадающих/вложенных путей, символической ссылки назначения и параллельного запуска; `logger` пишет SUCCESS/FAIL с кодом завершения. Для каждого пользователя нужен отдельный каталог назначения, если практику выполняют несколько аккаунтов.

[src/crontab.example](src/crontab.example): запуск каждый день в 04:00, пользовательский crontab; путь student заменить действительным. В `/etc/cron.d` формат отличается: требуется поле пользователя. Скрипт запускается bash, поэтому исполняемый бит самого файла необязателен. Реальная установка cron здесь не выполнялась.

На Linux после пробного запуска смотреть `journalctl -t netology-home-backup` либо syslog согласно настройкам rsyslog/journald. Ненулевой rsync (включая исчезнувший файл источника во время копирования) отмечается FAIL. При зависшем/аварийно остановленном процессе может остаться lock-каталог: сначала убедиться, что процесс не работает, затем убрать только этот замок.

## Реальная локальная проверка

[scripts/verify_local.py](scripts/verify_local.py) создал изолированные данные: проверены исключение скрытых каталогов и сохранение .profile, обнаружение изменения AAAA→BBBB при прежнем размере/mtime, удаление лишнего файла, полное зеркало, отказ на пересечение путей и оба результата журнала. Системный logger заменён тестовым файлом: настоящий Linux syslog не проверялся. [Результат](evidence/local-result.json).

![Учебная сводка, не снимок Linux/cron](examples/demo.svg)

`/tmp` может очищаться и находится на том же диске — это путь условия, а не надёжная долговременная стратегия. Зеркало также переносит случайные удаления, поэтому для рабочих данных нужны версии и отдельный носитель/сервер. Открытые БД требуют согласованного дампа/снимка, одного rsync недостаточно.
