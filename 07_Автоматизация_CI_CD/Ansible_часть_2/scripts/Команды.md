# Команды Ansible 2

## Уже выполненная безопасная локальная проверка

```bash
python3 scripts/verify_local.py
```

Скрипт выполняет пять `ansible-playbook --syntax-check` и рендер Jinja с учебными facts. Не вызывает playbook без --syntax-check и не подключается к хостам. Использует временный каталог для служебных файлов Ansible.

## Справочник для отдельного разрешённого Linux-стенда

Следующие команды в этом сеансе **не выполнялись**. `inventory.example.ini` содержит только адрес для документации 192.0.2.10, а не готовую VM. Перед настоящим запуском нужен отдельный приватный inventory с актуальным хостом. Контроллер — Mac, управляемая ОС — Debian/Ubuntu с systemd.

```bash
cd src
ansible-galaxy collection install -r requirements.yml
ansible-playbook -i /private/path/inventory.ini 1_kafka.yml
ansible-playbook -i /private/path/inventory.ini 2_tuned.yml
ansible-playbook -i /private/path/inventory.ini 3_motd.yml
ansible-playbook -i /private/path/inventory.ini 4_motd_v2.yml
ansible-playbook -i /private/path/inventory.ini 5_run_apache.yml
# При необходимости только для UFW на разрешённом стенде:
ansible-playbook -i /private/path/inventory.ini 5_run_apache.yml -e apache_manage_ufw=true
```

В задании запрещены shell/command внутри плейбуков; команды контроллера ansible-playbook этим запретом не являются. Для подтверждения повторяемости на Linux отдельно сравнивают второй запуск и PLAY RECAP. В данном самостоятельном режиме нового запуска не требуется.
